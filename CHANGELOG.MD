## Versioning

Where Semantic Versioning applies:

- **MAJOR:** Incompatible changes.
- **MINOR:** New functionality that remains backward compatible.
- **PATCH:** Backward-compatible fixes.

Engineering documents and physical engine configurations may also have independent revision numbers. A repository release does not automatically imply that a physical engine design has been validated.

## Release Policy

- Releases represent the state of the project repository at a specific point in time.
- Every release must have a corresponding changelog entry.
- Only changes that have been merged or accepted into the release branch are included.
- Experimental designs and unvalidated engineering proposals must be clearly identified.
- A software or documentation release does not constitute engineering approval or physical validation.
